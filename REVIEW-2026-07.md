# SysML v2 Tooling Review — vs. "The SysML v2 Book" (Weilkiens, Release 2026-05)

Systematic review of our three projects (tree-sitter-sysml grammar, sysml CLI + LSP,
sysml2-mode for Emacs) against the book's language reference and recommended modeling
practice. Method: extracted all **169 code listings** from the book epub and ran them
through every layer, then drove each tool through the book's Chapter 14 drone worked
example and the practice chapters (requirements, verification, units, variants, views,
execution).

**Baseline:** 27/169 listings fail the tree-sitter grammar, 25/169 fail the CLI parser
(24 overlap). Deduped: **14 distinct grammar gaps**, 3 book fragments/errata, 1
extraction artifact.

### Silent misparses (code "passes" but the tree is wrong)

1. `filter @SysML::PartDefinition` — qualified name split; `metadata_access_expression` captures only `SysML`, `PartDefinition` becomes a sibling identifier. Worst silent misparse: any consumer reads the wrong annotation type.
2. `variation`/`variant` modifiers are invisible: consumed as anonymous `_modifier` tokens outside the definition/usage node span (grammar.js ~580, 1421). A `variant part` is indistinguishable from a plain `part` in the CST — blocks all variant-aware tooling (Ch 35).
3. Invocation arguments flattened: `NominateLeader(activeDrones = drones)` loses the `=` binding; arrow-call chains parse as flat nested `binary_expression`s with no argument-list structure.
4. `#tag` prefix metadata is a detached sibling, not a child of the annotated element.

### CLI parser-layer bugs

- `sysml check` only surfaces `ERROR` nodes, not `MISSING` nodes — listings 078/079/082 have broken trees but report zero errors (crates/sysml-core/src/parser.rs).
- E002 duplicate-def check ignores package scope: two `action def FindTarget` in *different* packages are flagged as duplicates.

## 2. sysml CLI (user-workflow review)

### P0 bugs — book-idiomatic models are broken

1. **Name resolution requires `import` for fully-qualified cross-file refs**, contrary to SysML v2 root-namespace rules. Ch 14's model (zero imports) drowns in W004. (`resolver.rs`)
2. **Package short names never resolve**: `package <LIB> 'Library Package'` + `import LIB::*;` → W004. The resolver has no short_name handling at all. Every Ch 14/32/35 listing uses `<UAVSBA>`, `<DSRE>`, etc.
3. **`trace` is requirement-usage-blind**: on the fully-traced drone model it reports "0/1 satisfied, 0/1 verified". Only defs are indexed; `<REQ23>` usages, `satisfy X::Y::z;`, `satisfy r by part;`, and verification bindings are all invisible (query.rs:321-351). `show <file> REQ2` → "not found".
4. **Units are dropped**: `attribute mass = 250 [SI::kg]` reads as **0** in rollup/eval — `resolve.rs:122` does a bare `parse::<f64>()`. The conversion table in `sim/units.rs` is never invoked. Ch 24's whole point is that quantities carry units.
5. **Action-flow simulation executes wrong steps**: actions run before `start`, run twice, and *both* branches of a `decide` execute (listings 072/073).

### P1 bugs

6. `analyze run` silently returns no computed value and no error (listing-128).
7. Named/typed allocations (`allocation l2p : L2P allocate a to b { ... }`, Ch 34) → "No allocations found"; only bare `allocate` works.
8. `diagram --view NAME` is a byte-identical no-op — even for nonexistent views (builders.rs:1500-1514 silently returns). `expose`, metaclass filters, `render` clauses all ignored.
9. Parallel states (Ch 28.3) misreported as "deadlocked (0 steps)".
10. `show` invents attributes (hoists nested variant's `redefines`), omits doc text and requirement IDs; accepts only one file.

### Feature gaps (prioritized, book-motivated)

1. Variant modeling (Ch 35): `variation`/`variant` dropped entirely; no list/resolve/configure; no `--variant a=b` selector for rollup/diagram — configure-then-compute is the chapter's core workflow.
2. View/viewpoint execution (Ch 37/13) — see bug 8.
3. Metadata queries (Ch 36): no `find`/`list` filtering by metadata or attribute value; package `filter` conditions ignored.
4. Stdlib member validation: `ISQ::doesNotExist` passes (prefix whitelist only), despite the embedded 94-file stdlib.
5. Individuals/snapshots (Ch 25): `individual` modifier dropped from model/list/show.
6. `doc` omits requirement usages + their doc text — the artifact stakeholders actually want.

### Lint quality (144 parsing listings → 553 diagnostics)

- **W008 false positive on canonical calc form**: SysML calc bodies end with a result *expression* (Ch 27) — all 7 W008 hits flag correct code.
- **W001 unused is per-file** — fires on defs referenced by sibling files in the same invocation, and on root/context defs nothing should reference.
- **W002/W003/W014 are satisfy-form-blind and triple-redundant** — three warnings for one fact, still firing when `satisfy requirement : X;` is present.
- W004 "did you mean" suggests usages/stdlib internals for missing types; wording "not defined in this file" misleads in multi-file runs.

## 3. sysml-lsp

### P0 — users corrupt models or distrust diagnostics

1. **"Replace with X" quickfix deletes the declaration**: diagnostic span covers the whole usage, edit replaces it with just the type name → `part v : Vehicel;` becomes `Vehicle`. (code_actions.rs:20-39)
2. **Rename only edits open files** — closed files keep the old name (server.rs:577-596), and rename skips `import`, `satisfy`/`verify`/`connect`/`allocate`/flow references (rename.rs:15-92). Silent corruption of exactly the traceability the book teaches.
3. **Position-encoding chaos**: outgoing ranges are byte columns, incoming decoded as code points, semantic tokens bytes — contract is UTF-16. Every range after a non-ASCII char is misplaced (doc comments with umlauts are book house style).
4. **"Add import" code action is unreachable dead code**: diagnostics inject all workspace names into resolved_imports, suppressing the W004 that would trigger it — and genuinely missing imports are never diagnosed.
5. **W001 + "Remove unused" quickfix in multi-file projects** offers to delete definitions other files depend on.
6. 24/169 book listings show false E001 red squiggles (grammar gaps above) — ~14% of book code errors while typing along.

### P1 — the embedded stdlib is invisible

7. Type-position completion excludes stdlib entirely (`attribute mass : ` → 4 local items); `ISQ::` triggers an unscoped 1423-item dump that doesn't contain `mass`. `stdlib_package_defs()` exists but is never called by completion.
8. Hover/goto-definition return null for `Real`, `ISQ::mass`.

### P2

9. Workspace index keyed by simple name, last-writer-wins; explicit imports ignored in goto-definition (jumps to the wrong package's `Widget`).
10. **Type hierarchy implemented but never advertised** in initialize → clients never call it. One struct field to fix; also single-supertype-only.
11. Reference/highlight ranges are whole statements, duplicated per match; documentSymbol omits top-level usages (10/169 listings show empty outlines); documentLink always returns null (URI-vs-path confusion, document_link.rs:74-82).

Worth keeping as-is: hover rollups, codeLens satisfy/verify counts, did-you-mean, formatting, folding, workspace scan at init.

## 4. sysml2-mode (Emacs)

### P0

1. **Indent staircase after `}`**: `sysml2--calculate-indent` (sysml2-indent.el:139-169) has no case for a previous line ending in `}` → every sibling after a nested block drifts +4, compounding. Re-indent staircases 87/169 book listings. Related: lines after `*/` treated as continuations.
2. **Quoted names and `<shortName>` tags unsupported** (57/169 and 39/169 listings): `package 'Drone System'`, `requirement <REQ23> observeArea`. Consequences: requirement extraction returns nil for Ch 14 (sysml2-model.el:691 only accepts `<'ID'>`); imenu/which-function skip quoted-name elements; **goto-definition jumps to the wrong definition** (`'Air Frame'` → matches `Air`); qualified names truncate at quotes. Fix: shared name regexp `\(?:'[^']+'\|[A-Za-z_][A-Za-z0-9_]*\)` + optional `<...>` prefix threaded through lang/model/navigation/completion.

### P1

3. Missing keywords in sysml2-lang.el: `frame`, `render`, `at`, `locale` (all confirmed in book listings).
4. Model-extraction gaps (sysml2-model.el): multi-line `connect`/`flow` never match (`[ \t]+` needs `[ \t\n]`); `flow a.b to c.d` shorthand and typed flows unsupported; **no `message` extractor at all** (Ch 29); semicolon-body defs absorb the next block's members (`:191`, `:729`); variants/variations dropped (Ch 35); verification extractor misparses defs (`:924`); satisfy only handles the `by` form; qualified/multiple derives missed; **no metadata extractor** (Ch 36 status/priority reporting impossible); individuals/snapshots/timeslices not extracted; views: quoted names, qualified `render` targets, and `expose` unhandled, render alist has invented names and lacks real ones (`asElementTable`).

### P2

5. Snippet gaps (32 exist): `calc def`, `item def`, `occurrence def`, variation/variant block, `metadata def` + `@M {}`, `concern def`, `verification def` with objective, `analysis def`, `message`, standalone transition, `alias`, `interface def`, `perform`/`exhibit state`; requirement snippet should offer the `<ID>` slot.
6. Usability: no completion for Views-library render names; imenu can't navigate requirement usages.

## 5. Cross-cutting priorities (highest leverage first)

1. **Grammar G1+G2** (function literals, `then perform`) — unblocks the CLI, the LSP (false E001s), and the book's worked example in one stroke. Then G3-G6.
2. **Name resolution** (CLI root-namespace + short names; LSP qualified-name index + import awareness) — poisons check/trace/deps/diagrams/goto today.
3. **Requirement-usage traceability** (CLI trace/show/W002-W014; Emacs `<REQ23>` extraction) — requirements-as-usages with short-name IDs is *the* book pattern.
4. **Units** — parse `value [unit]` once in sysml-core, wire the existing conversion table through rollup/eval/analyze.
5. **LSP safety**: quickfix range, workspace-wide rename incl. imports/relations, one position encoding.
6. **Emacs indent + quoted names** — the two fixes that make the mode feel correct on any book file.
7. **Variants as first-class** (grammar CST nodes → model → CLI configure/rollup → Emacs extraction) — Ch 35 is a flagship v2 feature no tool currently represents.
